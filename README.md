<h1 align="center">IslamicKitPlus</h1>

<p align="center">
  Offline Islamic toolkit for Swift — prayer times, next prayer, Hijri calendar,
  qibla, calendars, and an offline city geocoder. English &amp; Arabic. No API calls.
</p>

---

`IslamicKitPlus` is the native Swift port of the Dart package
[`islamic_kit_plus`](https://github.com/bilalelsayed97/islamic_kit_plus). It
computes **everything on-device**. There are **no network requests** to
aladhan.com or any other service, and the port is **behaviourally identical**
to the Dart engine: the same numbers, the same strings, the same JSON, proven
by a cross-language conformance suite (see [Testing](#testing)).

Prayer times are solved from **Jean Meeus' solar position** (*Astronomical
Algorithms*, 2nd ed.), with the sun's right ascension and declination
interpolated across three days so every event is computed at the moment it
occurs rather than at a fixed seed hour. Around it sit the Moonsighting
Committee twilight, a Hijri calendar with four methods, and the qibla
calculation. JSON output mirrors the
[aladhan.com Prayer Times API](https://aladhan.com/prayer-times-api)
response **shape**.

The calculation core (prayer times, Hijri calendar, qibla, calendars) depends on
**Foundation only**. The optional by‑city / by‑address geocoder reads a bundled
SQLite database of **265,849 places** across 251 countries and 371 timezones —
131,090 of them populated settlements, which is what city search and reverse
geocoding match against.

## Highlights

- 🕌 **Prayer times** from the Meeus solar algorithm, with 34 calculation
  methods, Asr schools, high‑latitude rules, midnight modes, per‑prayer tuning,
  and elevation.
- 🌙 **Moonsighting Committee Worldwide** Fajr/Isha (general / red / white shafaq).
- 📅 **Hijri ↔ Gregorian** conversion with four calendar methods, month lengths,
  and Islamic holidays.
- 🗓️ **Calendars** — monthly, annual, and date‑range, in both Gregorian and Hijri.
- 🧭 **Qibla** direction (great‑circle bearing to the Ka'aba).
- 🏙️ **Offline geocoding** — bundled database of 265,849 places (131k
  settlements) with English + Arabic names, behind a swappable `Geocoder` protocol.
- 🌐 **EN/AR localization** for prayer, month, and weekday names, plus a
  `title` / `description` on every enum for building settings UIs.
- 🔌 **aladhan‑shaped** `toAladhanJson()` — the same response structure and key
  order, so an existing aladhan client parses it unchanged.
- 🧱 **Clean architecture**, `Sendable` value types, dependency‑free core,
  strict‑concurrency clean.
- 🔁 **Parity with the Dart package** — every Dart test ported, plus 55k+
  conformance cases generated by the Dart implementation.

## Install

### Swift Package Manager

```swift
// Package.swift
dependencies: [
    .package(url: "https://github.com/bilalelsayed97/islamic_kit_swift.git", from: "0.3.0"),
],
targets: [
    .target(
        name: "MyApp",
        dependencies: [
            .product(name: "IslamicKitPlus", package: "islamic_kit_swift"),
            // Only where you need the bundled city database:
            .product(name: "IslamicKitPlusGeocoding", package: "islamic_kit_swift"),
        ]
    ),
]
```

In Xcode: *File ▸ Add Package Dependencies…*, paste the URL, and add
`IslamicKitPlus` (and optionally `IslamicKitPlusGeocoding`) to your target.

Platforms: iOS 13, macOS 10.15, tvOS 13, watchOS 6. Swift tools 5.9.

### CocoaPods

```ruby
pod 'IslamicKitPlus'              # core only (default subspec)
pod 'IslamicKitPlus/Geocoding'    # core + the bundled city database
```

With CocoaPods both subspecs compile into the **single `IslamicKitPlus`
module** — there is no separate `IslamicKitPlusGeocoding` to import. The
podspec is `static_framework`, `APPLICATION_EXTENSION_API_ONLY`, and safe to
link from widget and other app‑extension targets.

## Two products

| Product | Import | Use it for |
|---|---|---|
| `IslamicKitPlus` | `import IslamicKitPlus` | The full core API: prayer times, Hijri calendar, qibla, calendars, aladhan JSON, EN/AR labels, and the curated 103‑city offline geocoder. Foundation only — no database, no SQLite. |
| `IslamicKitPlusGeocoding` | `import IslamicKitPlusGeocoding` (re‑exports the core) | Everything above **plus** `SqliteCityGeocoder` and `SqliteCityDirectory`, which read the bundled 37 MB `prayer_times.db`. Link it only in targets that need by‑city / by‑address lookups, city pickers or reverse geocoding. |

## Quick start

```swift
import IslamicKitPlus

let service = PrayerTimesService()

let result = try service.timings(
    CivilDate(year: 2014, month: 4, day: 24),
    Coordinates(51.508515, -0.1254872), // London
    CalculationParameters(
        method: .isna,
        utcOffset: UTCOffset(hours: 1) // London BST
    )
)

print(result.formatted(.fajr))            // 03:57
print(result.formatted(.asr, .h12))       // 4:56 pm
print(Prayer.maghrib.title(.ar))          // المغرب
print(result.date.hijri.day)              // 24  (24-06-1435)
```

`timings` throws (see [Errors](#errors)): the date block runs the Hijri
converter, which rejects dates outside its table.

## Zero-config & automatic per-location settings

You don't have to set every enum. There are four levels of "automatic":

**1. Sensible global defaults.** Every field of `CalculationParameters` has a
default (`method: .mwl`, `school: .standard`, `highLatitudeRule: .middleOfNight`,
`calendarMethod: .hjcosa`, `shafaq: .general`, `imsakMinutes: 10`, …), so you can
call `timings` with **no params** — you only supply the UTC offset:

```swift
try service.timings(
    CivilDate(year: 2024, month: 4, day: 24),
    Coordinates(21.42, 39.83),
    CalculationParameters(utcOffset: UTCOffset(hours: 3)) // that's it
)
```

**2. Fully automatic by city.** `timingsByCityAuto` needs **no presets at all** —
it picks the calculation method and Asr school from the city's country (the
offline equivalent of aladhan choosing "the closest authority based on location")
and takes the UTC offset from the city database:

```swift
import IslamicKitPlusGeocoding

let service = PrayerTimesService(geocoder: try SqliteCityGeocoder.bundled())

// No method, school, or offset needed — all inferred from "Cairo, EG":
let result = try service.timingsByCityAuto("Cairo", date: .today(), country: "EG")
```

**3. Recommended params you can reuse (e.g. with coordinates).** Get the
recommended method + school for a country and pass it anywhere (timings,
calendars, next prayer), overriding anything you like:

```swift
let params = service.recommendedParams("PK", utcOffset: UTCOffset(hours: 5))
// -> Karachi method + Hanafi school
try service.monthlyCalendar(2024, 4, coords, params)

// Or resolve straight from a country code:
let m: CalculationMethod = LocationDefaults.methodForCountry("US") // .isna
let s: AsrSchool = LocationDefaults.schoolForCountry("TR")         // .hanafi
```

**4. Fully automatic from a GPS fix.** With the city database open,
`autoParamsForCoordinates` takes a latitude and longitude, finds the nearest
city, and reads the calculation method from that city's country as recorded in
the database (all 251 of them) plus the UTC offset from its timezone:

```swift
import IslamicKitPlusGeocoding

let service = PrayerTimesService(directory: try SqliteCityDirectory.bundled())

// Everything inferred from the coordinates (nil if no city resolves):
let result = try service.timingsByCoordinatesAuto(21.4225, 39.8262, date: .today())
// -> Umm al-Qura, UTC+3

// Or just the parameters, to reuse elsewhere:
let params = try service.autoParamsForCoordinates(21.4225, 39.8262)
```

**Country → method** defaults (the fallback when the database is not open):
US/MX → ISNA, CA → Canada, SA/YE/BH/SY/VN → Makkah, AE → Dubai, KW → Kuwait,
QA → Qatar, OM → Oman, EG/NG → Egypt, SD/SS → Sudan, IQ → Iraq, LY → Libya,
JO → Jordan, DZ → Algeria, MA/EH → Morocco, TN → Tunisia, IR → Tehran,
TR → Turkey, RU → Russia, TJ → Tajikistan, PK/IN/BD/AF → Karachi,
MV → Maldives, ID/MY/SG → Singapore, BN → JAKIM, FR/MF → France, PT → Portugal,
DE → Munich, AT → Vienna, BE → Belgium, LU → Luxembourg — everything else →
Muslim World League. Hanafi Asr is the default for PK, IN, BD, AF, TR. All of
this is overridable.

> The one thing not auto-detected from the database is **daylight saving** —
> bundled city offsets are standard time. Foundation's `TimeZone` can fill the
> gap; see [Timezones & DST](#timezones--dst).

## Core concepts

| Type | What it is |
|---|---|
| `PrayerTimesService` | The **facade** you call for every feature. A `Sendable` final class — construct once and reuse. |
| `Coordinates(lat, lng)` | A geographic point in decimal degrees. |
| `CalculationParameters` | Value type holding all calculation settings. Mutate a copy, or use `with { }`, to tweak. |
| `CivilDate(year:month:day:)` | A calendar date with **no time zone** — the port of the date‑only `DateTime` the Dart package passes around. Month/day overflow normalises like Dart (`CivilDate(year: 2014, month: 2, day: 30)` is 2014‑03‑02); `today(in:)`, `addingDays`, `isoWeekday` (Mon = 1). |
| `CivilDateTime` | A `CivilDate` plus wall‑clock `hour`/`minute`/`second`; `now(in:)`. Used by `nextPrayer`. |
| `UTCOffset` | A fixed offset in seconds: `UTCOffset(hours: 5, minutes: 30)`, `.zero`, `UTCOffset(iso: "+05:30")`, `UTCOffset(timeZone:on:)`. The port of the Dart `Duration utcOffset`. |
| `PrayerResult` | The result of a timings call: `timings` + `date` (Gregorian + Hijri) + `meta`. |
| `PrayerTimings` | The set of computed times; `time(_:)`, `formatted(_:_:)`, `toFormattedMap()`, and `raw`. |
| `RawPrayerTimes` | The raw fractional hours, an 11‑slot table indexed by `Prayer` in declaration order; `raw[.fajr]` is `Double?` (`nil` = invalid). Iterable. |
| `PrayerTime` | A single time; `format(_:)`, `instant` (`Date?`), `epochMilliseconds`, `isValid`, `name(_:)`. |
| `NextPrayer` | The next upcoming prayer, its `time`, and the `onDate` it falls on. |
| `QiblaDirection` | Bearing to the Ka'aba (`degrees` clockwise from true north). |
| `IslamicKitError` | The one error type the core throws. |

### Errors

Where the Dart package throws `ArgumentError` / `StateError`, the Swift port
`throws IslamicKitError`, an `Equatable` enum whose `message` is the Dart text:

| Case | When |
|---|---|
| `.gregorianDateOutOfRange(String)` | A date outside a Hijri table's range (HJCoSA / UAQ: 1937‑03‑14 … 2077‑11‑16; Diyanet: 1900‑05‑01 … 2028‑01‑26). Every timings/calendar call can throw this because the date block runs the converter. |
| `.hijriDateOutOfRange(String)` | A Hijri date outside the table (UAQ 1356–1500 AH, Diyanet 1318–1449 AH). |
| `.invalidDateRange(String)` | `rangeCalendar` with `end` before `start` or a span over 11 months. |
| `.locationNotFound(query:)` | The geocoder returned nothing for a `*ByCity` / `*ByAddress` query. |
| `.directoryRequired` | `autoParamsForCoordinates` / `timingsByCoordinatesAuto` without a `directory:`. |
| `.twilightStrategyRequired(method:)` | `AstronomicalCalculator.compute` for Moonsighting without a strategy (never from the service). |

```swift
do {
    _ = try service.timings(CivilDate(year: 2100, month: 3, day: 1), coords, params)
} catch let error as IslamicKitError {
    print(error.message) // Gregorian date out of range for HJCoSA ((1937, 3, 14) .. (2077, 11, 16)).
}
```

## Configuration — `CalculationParameters`

Every setting is optional. Defaults are shown.

| Field | Type | Default | Description |
|---|---|---|---|
| `method` | `CalculationMethod` | `.mwl` | The twilight authority (see below). |
| `customMethod` | `MethodParams?` | `nil` | Angles/intervals used when `method` is `.custom`. |
| `school` | `AsrSchool` | `.standard` | Asr shadow factor (Standard = 1, Hanafi = 2). |
| `asrShadowFactor` | `Double?` | `nil` | Overrides the school's shadow factor when set. |
| `midnightMode` | `MidnightMode?` | `nil` | Overrides the midnight basis. Unset resolves to `.jafari` (sunset → Fajr), the engine's basis. |
| `highLatitudeRule` | `HighLatitudeRule` | `.middleOfNight` | High‑latitude Fajr/Isha bound. `.none` disables it. |
| `utcOffset` | `UTCOffset` | `.zero` | **You provide this.** Offset for the target date (include DST). |
| `elevation` | `Double` | `0` | Observer elevation in metres. Dips the horizon, so sunrise comes earlier and sunset later. A package extension — the reference engine assumes sea level. |
| `shafaq` | `Shafaq` | `.general` | Twilight used by the Moonsighting method for Isha. |
| `tune` | `Tune` | `.none` | Per‑prayer offsets in minutes (aladhan `tune`). |
| `imsakMinutes` | `Int` | `10` | Minutes before Fajr for Imsak. |
| `dhuhrMinutes` | `Int` | `0` | Minutes added to Dhuhr. |
| `calendarMethod` | `CalendarMethod` | `.hjcosa` | Hijri method for the date block. |
| `timezoneName` | `String?` | `nil` | Optional label echoed in `meta.timezone`. |

```swift
let base = CalculationParameters(method: .egypt)
let tuned = base.with {
    $0.school = .hanafi
    $0.utcOffset = UTCOffset(hours: 2)
    $0.tune = Tune(fajr: -2, isha: 3) // minutes; see "Per-prayer tuning"
}
```

`CalculationParameters` is a struct with `var` fields, so `var p = base;
p.school = .hanafi` works just as well; `with { }` is the one‑expression
spelling of Dart's `copyWith`.

### Per-prayer tuning (the aladhan `tune` parameter)

Shift any prayer by a number of minutes with `Tune`. Its field order matches the
aladhan contract exactly — `Imsak, Fajr, Sunrise, Dhuhr, Asr, Maghrib,
Sunset, Isha, Midnight` (Maghrib precedes Sunset) — so you can build it from, or
export it to, the aladhan `tune` CSV:

```swift
// Named fields
let tune = Tune(fajr: 3, dhuhr: 7, isha: 8)

// From/to the aladhan "tune" query string
let parsed = Tune(csv: "5,3,5,7,9,-1,0,8,-6")
parsed.csv // "5,3,5,7,9,-1,0,8,-6"

let params = CalculationParameters(
    method: .mwl,
    utcOffset: UTCOffset(hours: 3),
    tune: tune
)
```

The applied offsets are echoed in the aladhan `meta.offset` block, just like the API.

## Enums (with EN/AR labels)

Every input is a typed enum, and **every enum exposes localized UI metadata**:

```swift
let label = CalculationMethod.mwl.title(.ar)       // رابطة العالم الإسلامي
let help  = AsrSchool.hanafi.description(.en)      // explains the shadow factor
```

| Enum | Cases |
|---|---|
| `Prayer` | imsak, fajr, sunrise, dhuhr, asr, sunset, maghrib, isha, midnight, firstThird, lastThird |
| `CalculationMethod` | 33 methods (see table) + custom |
| `AsrSchool` | standard, hanafi |
| `MidnightMode` | standard, jafari |
| `HighLatitudeRule` | none, middleOfNight, oneSeventh, angleBased |
| `TimeFormat` | h24, h12, h12NoSuffix, float, iso8601 |
| `Shafaq` | general, ahmer, abyad |
| `CalendarMethod` | hjcosa, uaq, diyanet, mathematical |
| `Language` | en, ar |

All are `CaseIterable` and `Sendable`, declared in the Dart order (so
`allCases` matches Dart's `values`). `Prayer` also has `key` (aladhan JSON
key), `nameEn`, `nameAr`, `localizedName(_:)` and the failable `Prayer(key:)`.
Convert to/from aladhan integer ids via `CalculationMethod.fromId(3)`,
`AsrSchool.fromAladhanId(0)`, `MidnightMode.fromAladhanId(_:)`,
`HighLatitudeRule.fromAladhanId(_:)`; string codes via
`CalculationMethod.fromCode("MWL")`, `Shafaq.fromCode(_:)`,
`CalendarMethod.fromCode(_:)`. Unknown ids fall back the way the Dart package
does (`.mwl`, `.standard`, `.angleBased`, `.general`, `.hjcosa`).

### Ramadan

`.makkah` is the only method whose Isha interval changes with the season: Umm
al‑Qura lengthens 90 minutes to 120 for Ramadan. The switch is resolved from
the **date being computed** (against the Umm al‑Qura table, whatever
`calendarMethod` you chose), so a calendar generated months ahead still gets
it right. Dates the table cannot express are simply "not Ramadan".

### Custom method

```swift
let params = CalculationParameters(
    method: .custom,
    customMethod: MethodParams(fajrAngle: 18, ishaMinutesAfterMaghrib: 90),
    utcOffset: UTCOffset(hours: 3)
)
```

`MethodParams` fields: `fajrAngle`, `ishaAngle` **or** `ishaMinutesAfterMaghrib`
(plus `ramadanIshaMinutesAfterMaghrib`), `maghribAngle` **or**
`maghribMinutesAfterSunset`, `adjustments`, `midnightMode`, `location`.

## Reading & formatting times

`PrayerResult` gives you three views of each time:

```swift
let result = try service.timings(date, coords, params)

// 1) Formatted string
result.formatted(.fajr)            // "03:57"  (24h default)
result.formatted(.fajr, .h12)      // "3:57 am"
result.formatted(.fajr, .iso8601)  // "2014-04-24T03:57:00+01:00"

// 2) The PrayerTime object
let t = result.time(.maghrib)
t.isValid           // false only at extreme latitudes
t.format()          // "20:12"
t.instant           // Date? — the absolute instant
t.epochMilliseconds // Int?  — the same, as Unix milliseconds

// 3) A whole map, or the raw hours
result.timings.toFormattedMap()    // [Prayer: String]  [.fajr: "03:57", ...]
result.timings.raw[.fajr]          // Optional(3.95) — fractional hours, nil if invalid
for (prayer, hours) in result.timings.raw { _ = (prayer, hours) } // Prayer order
```

`TimeFormat` options: `.h24` (`03:57`), `.h12` (`3:57 am`), `.h12NoSuffix`
(`3:57`), `.float` (raw hours, e.g. `3.95`), `.iso8601`. Times that cannot be
computed return the sentinel `invalidTime` (`-----`).

Raw hours are relative to the *local* civil day and may run below 0 or past
24 when an event rolls into the neighbouring day (Last Third is often
`> 24`); the clock formats wrap, and `.iso8601` moves the date instead —
`2014-04-25T01:40:00+01:00` for an Isha after midnight.

## Prayer times

```swift
// By coordinates
try service.timings(CivilDate(year: 2024, month: 4, day: 24), Coordinates(21.42, 39.83), params)

// By city (see Geocoding for which geocoder answers)
try service.timingsByCity("Cairo", date: .today(), country: "EG", params: params)

// By free‑text address
try service.timingsByAddress("Trafalgar Square, London, UK", date: .today())
```

The `*ByCity` / `*ByAddress` helpers apply the city's standard‑time offset when
`params.utcOffset` is `.zero`, and leave an explicit offset alone.

## Next prayer

Returns the next obligatory prayer strictly after the given wall‑clock instant,
rolling to the next day's Fajr if you're past Isha:

```swift
let next = try service.nextPrayer(
    CivilDateTime(year: 2014, month: 4, day: 24, hour: 13, minute: 30), coords, params)
next.prayer        // .asr
next.time.format() // "16:56"
next.onDate        // 2014-04-24

try service.nextPrayerByAddress("London, UK", .now(), params)
```

`CivilDateTime.now(in:)` and `CivilDate.today(in:)` default to
`TimeZone.current`; pass the zone whose wall clock `params.utcOffset` describes.

## Calendars

```swift
// Gregorian
let month: [PrayerResult] = try service.monthlyCalendar(2024, 4, coords, params)
let year: [Int: [PrayerResult]] = try service.annualCalendar(2024, coords, params)
let range: [PrayerResult] = try service.rangeCalendar(
    CivilDate(year: 2024, month: 1, day: 1), CivilDate(year: 2024, month: 3, day: 31),
    coords, params) // ≤ 11 months, inclusive

// Hijri
let hMonth = try service.monthlyHijriCalendar(1446, 9, coords, params) // Ramadan
let hYear = try service.annualHijriCalendar(1446, coords, params)

// By city
try service.monthlyCalendarByCity(2024, 4, "London", country: "GB", params: params)
try service.monthlyHijriCalendarByCity(1446, 9, "Cairo", country: "EG", params: params)
```

## Hijri calendar conversion

```swift
let factory = HijriConverterFactory()

let hijri = try factory.create(.hjcosa)
    .fromGregorian(CivilDate(year: 2025, month: 2, day: 14))
hijri.day         // 15
hijri.month       // 8
hijri.monthEn     // "Sha'ban"
hijri.monthAr     // Arabic month name
hijri.monthLength // 29
hijri.formatted   // "15-08-1446"
hijri.holidays    // Islamic observances on this day (may be empty)

let gregorian = try factory.create(.uaq)
    .toGregorian(year: 1446, month: 8, day: 15) // 2025-02-14
```

| Method | Basis | Valid range |
|---|---|---|
| `.hjcosa` (default) | Umm al‑Qura table + Saudi sighting overrides | 1356–1500 AH |
| `.uaq` | Umm al‑Qura table | 1356–1500 AH |
| `.diyanet` | Diyanet table | 1318–1449 AH |
| `.mathematical` | Pure arithmetic; supports a day `adjustment` | unrestricted |

```swift
// Mathematical supports a +/- day adjustment in both directions
try factory.create(.mathematical)
    .fromGregorian(CivilDate(year: 2025, month: 2, day: 14), adjustment: 1) // day 16
try factory.create(.mathematical)
    .toGregorian(year: 1446, month: 8, day: 15, adjustment: -1)            // 2025-02-13
```

Out‑of‑range dates on table methods throw `IslamicKitError.gregorianDateOutOfRange`
/ `.hijriDateOutOfRange`. The same date gives 1446‑08‑15 under HJCoSA and
UAQ (a 29‑day month) and under the mathematical calendar (30 days), but
1446‑08‑16 (30 days) under Diyanet — the tables genuinely differ.

q.degrees // 118.98724271029 — clockwise from true north

## Geocoding

By‑city / by‑address lookups go through the `Geocoder` **protocol**, so you can
choose your source or plug in your own.

### Option A — bundled SQLite database (recommended)

`IslamicKitPlusGeocoding` ships a 265,849‑place database — 131,090 populated
settlements plus their administrative divisions — with English + Arabic names,
coordinates and standard‑time offsets. The file is **opened in place, read‑only**
inside the resource bundle (`immutable=1`, no journal sidecars, nothing copied),
so opening is cheap. Open it once and keep the instance for the process
lifetime:

```swift
import IslamicKitPlusGeocoding

let geocoder = try SqliteCityGeocoder.bundled()
let service = PrayerTimesService(geocoder: geocoder)

try service.timingsByCity("London", date: .today(), country: "GB")
```

To open a copy you placed elsewhere, use a path:

```swift
let geocoder = try SqliteCityGeocoder(path: "/path/to/prayer_times.db")
```

The `state` argument of `search` / `resolve` is ignored by this geocoder and
`City.state` is always `nil` — the bundled database has no administrative‑region
column. `City.utcOffset` is the standard‑time offset and does not account for DST.

#### Widgets and other app extensions

A Swift package resource travels with every target that links the product:
an app **and** a widget extension that both depend on `IslamicKitPlusGeocoding`
each embed their **own 37 MB copy** of `prayer_times.db`. Two ways to avoid
that:

- **Resolve in the app, compute in the extension.** Link the geocoding product
  only in the app. Resolve the location once (`nearestCity`,
  `autoParamsForCoordinates`, or a picker) and store the resulting
  `Coordinates` and `CalculationParameters` in your App Group (for example in
  a shared `UserDefaults` suite). The extension links only `IslamicKitPlus` —
  Foundation, no database — and calls `timings` / `nextPrayer` from those
  values. This is the layout the package is designed for.
- **Share one on‑disk copy.** If the extension itself must look cities up,
  copy the database into the App Group container once from the app and open
  it **by path** from any process:

  ```swift
  let container = FileManager.default
      .containerURL(forSecurityApplicationGroupIdentifier: "group.com.example.app")!
  let dbURL = try BundledCityDatabase.materialize(into: container) // copies once, reuses after
  let directory = try SqliteCityDirectory(path: dbURL.path)
  ```

  `materialize(into:)` writes `islamic_kit_plus_prayer_times_v2.db`, reuses
  it when it already exists and is non‑empty, and copies through a temporary
  file so an interrupted copy never leaves a truncated database. Note that
  the `SqliteCity*` classes live in the geocoding product, so a target that
  opens the copy still links that product; to keep the second embedded
  resource out of the extension, prefer the first layout.

### Option B — curated, zero‑dependency fallback

The default geocoder (`BundledCityGeocoder`) is a small curated set of 103
cities that needs no database and works everywhere:

```swift
let service = PrayerTimesService() // uses BundledCityGeocoder
try service.timingsByCity("London", date: .today(), country: "GB")
```

### Option C — your own geocoder

```swift
struct MyGeocoder: Geocoder {
    func search(_ query: String, country: String?, state: String?) -> [City] {
        [ /* ... */ ]
    }
}

let service = PrayerTimesService(geocoder: MyGeocoder())
```

`resolve(_:country:state:)` (first match) comes free from the protocol
extension. `country` accepts an ISO‑3166 alpha‑2 code (`"GB"`) or a common name
(`"United Kingdom"`).

## City directory (pickers & reverse geocoding)

`Geocoder` answers *"which city is this text?"*. `CityDirectory` — a protocol in
the core, implemented by `SqliteCityDirectory` in the geocoding product — answers
the questions a location‑picker asks instead, reading English and Arabic names
together so either locale renders without a second lookup:

```swift
import IslamicKitPlusGeocoding

let directory = try SqliteCityDirectory.bundled()

directory.countries(query: "مصر")          // -> [CountryInfo(Egypt, EG)]
directory.citiesInCountry(65, limit: 50)    // most prominent first, paged
directory.searchCities(query: "Cairo")      // matches either language
directory.nearestCity(30.06263, 31.24967)   // -> CityEntry(Cairo, EG), Africa/Cairo
directory.timeZonesForCountry(65)           // -> [Africa/Cairo + Arabic label]
```

Two behaviours are worth knowing, because the naive query gets both wrong:

- **`nearestCity` is not a plain proximity sort.** The database records
  neighbourhoods alongside the cities containing them, so the closest row to
  central Cairo is a neighbourhood, not Cairo. Distance is weighted by
  settlement prominence, letting a nearby capital or administrative seat
  outrank a marginally closer suburb.
- **`timeZonesForCountry` filters border noise.** A handful of Egyptian border
  towns carry `Asia/Jerusalem`, which would present Egypt as a four‑zone
  country. A zone is offered only when it covers at least 0.5% of the country's
  populated places.

The database keys countries by an integer `country_id`; `CountryIsoMap.idToIso`
and `CountryIsoMap.isoToId` are public for callers that persist or branch on
ISO codes. `CountryInfo.calculationMethod` / `CityEntry.calculationMethod`
translate the database's own `calc_method` numbering through
`BundledMethodMap` (those ids are **not** aladhan ids).

## Localization

Two languages are provided: English and Arabic (`Language.en` / `Language.ar`).

```swift
// Prayer / month / weekday names on results
result.time(.fajr).name(.ar)      // الفجر
result.date.hijri.monthAr         // Arabic Hijri month
result.date.hijri.weekdayAr       // Arabic weekday

// UI metadata on every enum
CalculationMethod.makkah.title(.en)          // "Umm al-Qura"
HighLatitudeRule.angleBased.description(.ar)
```

The name tables live in `Localizer` (Hijri/Gregorian months and weekdays as
`LocalizedName { en, ar }`). Prayer names live on the `Prayer` enum. Every
string is byte‑identical to the Dart package (they are generated from it).

## aladhan-compatible JSON

Produce the exact response shape used by the aladhan Prayer Times API. The
serializers return `JSONObject`, an **insertion‑ordered** JSON model whose
`serialized()` output matches Dart's `jsonEncode` character for character —
key order included (`hijri` before `gregorian`, the fixed nine‑key `offset`
block, whole doubles as `18` rather than `18.0`):

```swift
let json: JSONObject = result.toAladhanJson()
json["data"]?["timings"]?["Fajr"]?.string   // "03:57"
json["data"]?["meta"]?["method"]?["id"]?.int // 2

let text = json.serialized()               // compact, Dart jsonEncode form
let pretty = json.serialized(indent: "  ") // JsonEncoder.withIndent form
// {
//   "code": 200, "status": "OK",
//   "data": {
//     "timings": { "Imsak": "03:47", "Fajr": "03:57", ... },
//     "date": { "readable": "24 Apr 2014", "timestamp": "1398294000",
//               "hijri": { ...ar names, holidays... }, "gregorian": { ... } },
//     "meta": { "latitude": 51.508515, "method": {...}, "school": "STANDARD", ... }
//   }
// }

calendarAladhanJson(month)                 // data: [ ...day objects ]  (with " (tz)" suffix)
annualCalendarAladhanJson(year)            // data: { "1": [...], ..., "12": [...] }
nextPrayerAladhanJson(result, .asr)        // single‑entry timings
methodsAladhanJson()                       // the /methods response
qiblaAladhanJson(service.qibla(coords))
```

Choose a format: `result.toAladhanJson(format: .iso8601)`. `JSONValue` is
expressible by literals, so you can also build or patch documents by hand.

## Timezones & DST

The package intentionally ships **no timezone database** in the calculation
core. You pass `utcOffset` for the target date and **include DST yourself** (for
London that's `UTCOffset(hours: 1)` in summer, `.zero` in winter). The bundled
geocoder stores each city's *standard‑time* offset, which the `*ByCity` /
`*ByAddress` helpers apply automatically unless you set `utcOffset` explicitly.

On Apple platforms Foundation already knows the rules, so the DST‑correct offset
for a date is one line — and `CityEntry.timeZoneId` gives you the IANA name to
feed it:

```swift
let date = CivilDate(year: 2014, month: 4, day: 24)
let london = TimeZone(identifier: "Europe/London")!
let offset = UTCOffset(timeZone: london, on: date) // +01:00 (BST); the offset at local noon
let params = CalculationParameters(method: .isna, utcOffset: offset, timezoneName: london.identifier)
```

`UTCOffset(timeZone:at:)` takes a `Date` instead, and `PrayerTime.instant`
gives you the absolute `Date` to display in whatever zone you like.

## Concurrency

The package builds with strict concurrency checking (`StrictConcurrency`
upcoming feature) and is warning‑free under `-strict-concurrency=complete`:

- Every value type (`CivilDate`, `CalculationParameters`, `PrayerResult`,
  `JSONValue`, …) and enum is `Sendable`.
- `PrayerTimesService` is a `Sendable` final class with only `let` state;
  share one instance across tasks and actors freely.
- `Geocoder`, `CityDirectory`, `HijriConverter` and `TwilightStrategy` are
  `Sendable` protocols, so your own implementations must be too.
- `SqliteCityGeocoder` and `SqliteCityDirectory` are `@unchecked Sendable`:
  each call takes an `NSLock` and runs on the **one** underlying SQLite
  connection, so concurrent calls are safe but serialize. Queries take
  milliseconds; if you fan out many lookups, do them off the main actor.

## Architecture

Clean, layered, and dependency‑inverted, mirroring the Dart package one file per
file. Dependencies point inward.

```
Sources/IslamicKitPlus/                    # product IslamicKitPlus (Foundation only)
  Domain/
    Enums/              Prayer, CalculationMethod, AsrSchool, … + EN/AR localization
    ValueObjects/       CalculationParameters, Coordinates, MethodParams,
                        MethodAdjustments, Tune, CivilDate, CivilDateTime, UTCOffset
    Models/             PrayerTime (+ RawPrayerTimes, PrayerTimings), PrayerResult,
                        NextPrayer, DateInfo, GregorianDate, HijriDate, CalculationMeta,
                        QiblaDirection, City, CityEntry, CountryInfo, TimeZoneInfo
    Ports/              Geocoder, CityDirectory, HijriConverter, TwilightStrategy
    Services/           TimeFormatting (invalidTime, fixHour, formatHours)
    Errors/             IslamicKitError
  Application/
    PrayerTimesService  (facade), PrayerCalculator
    Serialization/      JSONValue (ordered), DartNumberFormatting, AladhanSerializer
    UseCases/           QiblaCalculator
  Infrastructure/
    Astronomy/          Astronomical, SolarCoordinates, SolarTime, AstronomicalCalculator
    Twilight/           MoonsightingTwilight
    Calendar/           JulianDayMath, TableHijriConverter, HjcosaConverter,
                        MathematicalConverter, HijriDateBuilder, HijriConverterFactory
                        Data/ Umm al‑Qura + Diyanet tables, holidays, sightings (generated)
    Config/             LocationDefaults, BundledMethodMap
    Geocoding/          BundledCityGeocoder (curated), GeocoderMatching
                        Data/ CityDataset, CountryIsoMap (generated)
    Localization/       Localizer
    Support/            IntegerMath (floorDiv/floorMod/javaRound), StringHelpers

Sources/IslamicKitPlusGeocoding/           # product IslamicKitPlusGeocoding
  SQLite/               SQLiteDatabase, SQLiteStatement, SQLiteRow, SQLiteError
  SqliteCityGeocoder, SqliteCityDirectory, BundledCityDatabase, Bundle+Geocoding
  Resources/prayer_times.db                (37,093,376 bytes, PRAGMA user_version = 2)
```

- **Ports** (`Geocoder`, `CityDirectory`, `HijriConverter`, `TwilightStrategy`)
  are protocols in the domain; concrete adapters live in infrastructure or the
  geocoding product and are injected via the service initializer.
- **Strategy** for time formats, high‑latitude rules, and twilight; **Factory**
  for Hijri converters; **Facade** for the top‑level API; **Value Objects**
  throughout.
- Files marked *generated* are emitted by the Dart package's
  `tool/generate_native_data.dart`, so every table and Unicode literal is
  byte‑identical to Dart.

## Parity notes

Every deviation from the Dart package is deliberate and listed here. Anything
not on this list is meant to match exactly — a mismatch is a bug.

| Dart | Swift | Why |
|---|---|---|
| `ArgumentError` / `StateError` | `throws IslamicKitError` (`.gregorianDateOutOfRange`, `.hijriDateOutOfRange`, `.invalidDateRange`, `.locationNotFound`, `.directoryRequired`, `.twilightStrategyRequired`); `message` carries the Dart text | Typed, checked errors are the Swift idiom; `timings*`, `nextPrayer*`, every calendar and the Hijri converters are `throws`. |
| `Prayer.fromKey(key)` throws on unknown | `Prayer(key:)` is failable (`nil`) | Failable initializers are how Swift spells "may not exist". |
| `CityDirectory` is a concrete SQLite‑backed class (loaded via `loadBundledCityDirectory()` in the Flutter entrypoint) | `CityDirectory` is a protocol in the core; `SqliteCityDirectory` implements it in the geocoding product | The core must stay SQLite‑free, yet the facade needs the port for `autoParamsForCoordinates`. |
| `copyWith(...)` on `const` value objects | `public var` fields on structs, plus `with { $0.x = … }` | Value semantics give the same immutability guarantees; `with` can also clear optionals, which `copyWith` cannot. `MethodParams.forRamadan()` is kept. |
| `DateTime` / `Duration` | `CivilDate`, `CivilDateTime`, `UTCOffset` | The engine is timezone‑free; these types make that explicit and reproduce Dart's date normalisation without Foundation's calendar. Foundation conveniences are additive. |
| ISO‑8601 formatting adds minutes to a local `DateTime` | Civil‑date arithmetic only (no host time zone) | Fixes a latent host‑DST leak in the Dart path; the fixtures are generated under `TZ=UTC`, where both agree. |
| `List.sort` (unstable) in the geocoders | Stable ordering with a deterministic tiebreak (record / row index) after `(score, rank)` | Dart leaves tie order unspecified; fixtures pin only unique winners. |
| `double.toString()` for `.float` and JSON doubles | `DartNumberFormatting` — shortest round‑trip digits laid out by Dart's rules (`13.0`, `1e21`, `1e-7`) | Swift's `description` differs in exponent thresholds; the port reproduces Dart's so the strings match. |
| `sqlite3` exceptions propagate | `SqliteCityGeocoder` / `SqliteCityDirectory` return `[]` / `nil` on a query failure; opening (`bundled()`, `init(path:)`) still throws `SQLiteError` | A valid bundled database never fails a query; a crash inside a widget is worse than an empty list. |
| `Map<Prayer, double?>` raw timings | `RawPrayerTimes` (11‑slot table in `Prayer` order) | Enum order and `nil` semantics are exact without a dictionary's unordered keys. |
| `Map<String, dynamic>` + `jsonEncode` | `JSONValue` / `JSONObject` (insertion‑ordered) + `serialized()` | Swift dictionaries and `JSONEncoder` do not preserve key order, which the aladhan shape depends on. |
| `Duration` UTC offsets in `City` | `UTCOffset` | As above. |
