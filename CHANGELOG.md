# Changelog

All notable changes to this package are documented here. The version's
major.minor tracks the Dart `islamic_kit_plus` engine it reproduces; the
patch component is independent.

## 0.3.1

### Fixed
- **Hijri → Gregorian was wrong for the table methods** (Umm al-Qura, Diyanet,
  HJCoSA). `toGregorian` ignored the lunation table that `fromGregorian` reads
  and used the arithmetic (tabular) calendar instead — a defect inherited, via
  the Dart reference, from the PHP original — so the two directions disagreed
  by a day or two wherever the observed month start differs from the tabular
  one: 1 Muharram 1448 converted to 17 June 2026, a day `fromGregorian` calls
  2 Muharram. 3,411 of the 11,888 reference cases (29%) were affected.
  `toGregorian` now reads the same table backwards, so the two directions are
  exact inverses for every day of both tables, and the Hijri calendars of
  `PrayerTimesService` start each month on its 1st. `fromGregorian`, the
  mathematical method and the HJCoSA announced dates are unchanged;
  `adjustment` still shifts the result by whole days.
- HJCoSA caveat, unchanged: an announcement moves single days (the 1st, the
  10th) of a month between 2003 and 2021, which the surrounding days, still
  read off the table, cannot mirror.

### Changed
- Conformance fixtures re-synced from the fixed Dart reference (generated at
  `e9dde03c958875519c2f291b2c625adc371b12cd`): `hijri.json` and
  `calendars.json` changed, every other fixture is byte-identical.
- New exhaustive round-trip tests (every day of each table).

## 0.3.0

Initial release: a behavioural Swift port of
[`islamic_kit_plus`](https://github.com/bilalelsayed97/islamic_kit_plus)
0.3.0 — same numbers, same strings, same JSON shape, same fallbacks.

Parity is proven two ways: every Dart test is ported 1:1, and the suite
asserts the cross-language conformance fixtures generated by the Dart
package (`tool/conformance/generate.dart` at git SHA
`1bd306ec2fc624694a4f43b556d5de0ef5d55aa7`, package 0.3.1 — a tooling-only
release over the 0.3.0 engine): 3,808 timings-matrix cases, 58 detailed
timings cases, 49,655 Hijri conversions, 45 qibla bearings, 90 next-prayer
cases, 10 calendars, 1,332 Moonsighting twilight values and 60 geocoder
searches, plus the aladhan envelopes and every localization string.

### Added
- `IslamicKitPlus` product (Foundation only): `PrayerTimesService` facade —
  timings by coordinates / city / address, fully automatic settings
  (`recommendedParams`, `timingsByCityAuto`, `autoParamsForCoordinates`,
  `timingsByCoordinatesAuto`), next prayer, qibla, monthly / annual / range
  and Hijri calendars; the Meeus solar engine with three-day interpolation,
  34 calculation methods with their published minute adjustments, Umm
  al-Qura's Ramadan Isha interval, Moonsighting Committee twilight,
  high-latitude rules, midnight modes, per-prayer `Tune`, elevation; a
  four-method Hijri calendar (HJCoSA, Umm al-Qura, Diyanet, mathematical)
  with holidays; EN/AR `title`/`description` on every enum; an
  insertion-ordered `JSONValue` and the aladhan-compatible serializers;
  `LocationDefaults`, `BundledMethodMap`, `CountryIsoMap` and the curated
  103-city `BundledCityGeocoder`.
- `IslamicKitPlusGeocoding` product: `SqliteCityGeocoder` and
  `SqliteCityDirectory` over the bundled `prayer_times.db` (265,849 places,
  37,093,376 bytes, schema `user_version` 2), opened read-only in place
  through a minimal `SQLiteDatabase` wrapper; `BundledCityDatabase` for
  locating the file or materializing a copy into an App Group container.
- `CivilDate`, `CivilDateTime` and `UTCOffset` value types replacing Dart's
  `DateTime`/`Duration`, with `Foundation` conveniences (`today(in:)`,
  `now(in:)`, `UTCOffset(timeZone:on:)`).
- `IslamicKitPlus.podspec` with `Core` (default) and `Geocoding` subspecs.

### Deviations from the Dart package
Deliberate; each is listed with its rationale under "Parity notes" in
`README.md`: errors are thrown (`IslamicKitError`) instead of Dart's
`ArgumentError`/`StateError`; `Prayer(key:)` is failable; `CityDirectory`
is a core protocol implemented by `SqliteCityDirectory`; value objects use
`var` fields and `with {}` instead of `copyWith`; the ISO-8601 formatter
uses civil-date arithmetic only; geocoder sort ties are broken
deterministically; the `float` format and JSON doubles use a Dart-compatible
shortest-round-trip formatter; SQLite failures yield empty results.
